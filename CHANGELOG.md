# Changelog

**English** · [Deutsch](CHANGELOG.de.md)

Notable changes per version. Versions follow `package.json`.

## Unreleased

- **A fallback voice model no longer costs the call.** If the main model rejected the session because of a limit and the fallback model then failed as well, the call was aborted while ringing. Now a fallback model that fails during setup makes way for the next one, whatever the reason; when none is left, the main model is tried once more. Gemini models that reject the "BLOCKING" setting for tools get the tools without it.
- **The "KI unterbrochen" note is in the right place.** If the AI's next answer was already running, the note appeared in the transcript only after it. If the text of the cut-off answer is already in the transcript, the note now appears at once.
- **Agent calls: asking back unprompted.** If the other party asks something about the agent, the call or the task that the AI does not know (for example what the agent did before), it asks the agent of its own accord and does not hang up before. The rule now stands on its own and is also part of the tool description. If the AI still answers such a question with "I don't know", the app notices it in the transcript and has it ask the agent right afterwards (twice per call at most); for questions unrelated to the agent or the call the answer stands. It answers questions about where the call comes from using the task and the background knowledge.
- **Gemini: long sentences stay open.** The eight-second safety limit for a missing end of speech no longer applies while the other party was audible by level within the last two and a half seconds (30 seconds at most).
- **Import contacts from an address book.** "Kontakte importieren" on the "Kontakte" page takes contacts with phone numbers from Google Contacts (People API), Microsoft (Outlook.com, Microsoft 365; Microsoft Graph) or a vCard/CSV file, which is the way for Apple iCloud. A list with search and a summary (new, partly there, already there) comes first; you import all new entries or the ones you tick, only on an explicit click. Numbers are converted to the SIPFunk format, several numbers per entry are kept. Existing contacts are never overwritten; only on request do they gain missing numbers. Access is read-only and lives in memory only (no token file); "Trennen" discards it. If the build ships a built-in app registration, "Verbinden" (connect) is enough: sign in, allow, and the address book loads by itself. Without it, or if you prefer, you register your own app, which then takes precedence; the steps are in the dialog under "Einrichtung" (setup) with direct links and in the user guide (section 11.1).
- **Further numbers per contact.** A contact can have further numbers besides the one that is dialled ("Weitere Nummern"); they are recognised on incoming calls and count for duplicates.
- **The text model helps decide during the call.** Until now it was only asked before the call (call plan) and afterwards (summary); during the call, word lists and fixed rules decided, and they were extended one by one after test calls. Now the text model of the AI connection knows the task, the plan (except in agent calls) and the whole transcript (the director also the voice AI's complete instructions) during the call and helps decide at three points (user guide, section 6.3):
  - **On hanging up** it checks point by point whether anything from the task is missing that can still be done. The check runs alongside the goodbye, so there is no pause before it. If the other party has only just answered and the transcription is still missing, the check waits up to 1.5 seconds for it. If something is missing, SIPFunk takes back the hang-up and the AI raises the point ("Eine Sache noch: …", one more thing). In return the voice AI's self-check against the call plan is dropped; it often led to awkward follow-up questions. This check now also exists without a call plan, i.e. on the answering machine and in agent calls.
  - **After the goodbye** it decides whether the other party is only saying farewell or still wants something. The word list did not know "Ihnen auch einen schönen Feierabend", for example, and took back the hang-up.
  - **Director in the background**: it reads along after each turn of the AI and gives it a hint only when needed (a question passed over, a misunderstanding, a forgotten point). The hint appears in the transcript.

  After the goodbye SIPFunk waits for what the other party says: for the transcription up to 4 seconds after the end of the utterance. An empty transcription (pure noise) counts as a farewell; without any transcription the call continues. In any case SIPFunk hangs up at the latest one minute after the AI began to end the call (even if the other party keeps talking or the speech detection keeps flickering; an attempt that SIPFunk rejects because the AI said something in the same turn does not start the minute), unless the hang-up was taken back and the call continues. If there are words, the text model has up to 4 seconds more to decide, otherwise the former word list does. If the text model does not answer in time on hanging up, the call ends as the voice AI decided (hanging up waits for the verdict for at most 8 seconds after the AI asked to end). The AI disclosure, limits, permissions and everything time-critical stay fixed: interruptions in mid-sentence are still decided by the word list, because a text model was measured at mostly three to four seconds, occasionally up to eight. In the spam defence it does not take part. **This is switched on:** the director costs one short text-model request per turn of the AI, and the transcript goes to your provider's text model during the call already. Switch it off under "Einstellungen › Technik › Textmodell entscheidet im Gespräch mit" (`AI_LIVE_JUDGE`).
- **MCP: the agent knows the whole conversation at any time.** `wait_for_events` now also reports silence and nudges, sounds without words, a repeated AI introduction, the check before hanging up and the AI's call plan (the plan only if the agent knows the target by name). The first line states the time left; during the call "Lage jetzt" follows: who is speaking, how long it has been silent, whether the AI is waiting for the agent or saying goodbye. In agent calls the agent is the director; it can take back the hang-up with `say` as before. The check before hanging up neither checks nor takes back a hang-up the agent requests (what the other party says after the goodbye can still continue the call). Only a direction from the agent (`say`) withdraws such a request, even before the AI has ended; the voice AI is told, and its next end is then checked again like any other. Tool descriptions and the example skill are updated.
- **Transcript: silence and sounds without words appear as a line in the record** ("Stille: Seit 6 s sagt niemand etwas – die KI wurde angestoßen"), as does a repeated AI introduction.
- **Simulator: two scenarios for special cases** (`ausweichen`, `vergessen`), and it uses the check on hanging up and the director like the app; `--no-judge` switches both off.
- **The AI reacts to sounds without words.** If the other party laughs or clears their throat, the provider's speech detection often reports nothing, and after six seconds the AI asked "are you still there?". SIPFunk now listens to the level: after a clear sound of at least 0.35 s followed by 1.2 s of quiet, the AI is told that the other party has audibly reacted and briefly responds to it. If something was audible just before, the stall watchdog also waits longer, and its question first picks up what was said last.
- **MCP: introduction as an AI also to your own number, with a check.** For agent calls to an owner number the AI now explicitly introduces itself as an AI assistant (until now only "Lara hier"). For all outgoing calls with AI disclosure SIPFunk checks the transcription of the first answer: if the reference to the AI is missing or the introduction was cut off, the AI makes up for it in its next sentence.
- **Gemini: noise limit from the end of speech also for the first utterance.** The first longer sentence of a call still counted as noise after two seconds.
- **Gemini: an echo of its own voice no longer interrupts the AI.** If Gemini detects speech while the AI is still speaking, the output now pauses instead of discarding the rest at once. If the transcription only repeats words the AI has just said in this answer (echo from the other party's phone), or if it was only a listening sound, the AI finishes its sentence. Questions, numbers and single answer words such as "ja", "nein" or "Moment" always count as a real interjection.
- **The AI is told when its sentence was cut off.** It then repeats the missing part on purpose instead of assuming a disturbed connection.
- **Every interruption has its own note** in the transcript and for the agent, with the beginning of the answer concerned; with two interruptions shortly after each other the first one used to be lost.
- **No forgotten question after the goodbye any more.** If the AI tried to hang up with a spoken goodbye, it only learned at the next attempt that a step of the call plan was missing, and then asked after both sides had already said goodbye. The check of the plan steps now comes with the first attempt to hang up.
- **Dodged questions.** If the other party dodges a question from the task with a counter-question or a change of subject, the AI briefly answers what they want to know and then asks its question once more. After a refusal or a second dodge it leaves it and records the point as open.
- **MCP: the call plan for agent calls can be switched off, default off.** New switch "Gesprächsplan vor Agenten-Anrufen erstellen" (create a call plan before agent calls) under "Einstellungen › MCP-Schnittstelle". When off, the AI calls with the agent's task only; the request to the text model before the call is answered is dropped, and with it the check of the plan steps before hanging up. The summary after the call stays. **Until now the plan was always created; if you want to keep it for agent calls, switch it on.**
- **The AI starts speaking sooner.** If the other party says nothing after picking up, the AI now greets after 1.5 instead of 2.5 seconds ("Warten nach Abnehmen" under "Einstellungen › Technik"). The new default only applies where the value has not been saved already.
- **MCP: a direction from the agent still arrives while the call is ending.** If the agent sends `say` while the AI is already saying goodbye, SIPFunk takes the hang-up back and the AI still says it; until now it was rejected with "Das Gespräch wird gerade beendet". It is only rejected once the call has been hung up. The log records every direction with its time.
- **MCP: asked "what did the agent want?", the AI names the task.** The rule about the agent that started the call made the AI answer that it wanted "nothing in particular".
- **Text model: a timeout counts as overload.** If a text model does not answer or the provider cannot be reached, the next fallback model takes over. For the call plan the limit is eight seconds per model instead of one minute.
- **The note "KI unterbrochen" (AI interrupted) stands after the sentence it refers to** instead of before it.
- **Fallback models for limits and overload.** Every AI connection has two new lists to tick, "Ausweich-Sprachmodelle" (fallback voice models) and "Ausweich-Textmodelle" (fallback text models). If the text model reports a limit or an overload (such as 429 or 503), the next ticked model answers; until now the call plan or the summary was then missing. If the provider rejects a call for such a reason while the voice session is being set up, SIPFunk sets it up again with the next ticked voice model. There is no switch during a running call. Without a tick nothing changes.
- **Gemini: longer sentences no longer count as noise in mid-speech.** With Gemini the transcription only arrives after the end of the sentence, but the two-second limit was counted from the start of speech. If Gemini reports the end of speech itself, the limit now counts from there. The log names what ended an utterance.
- **Cut-off answers are visible.** If the other party interrupts the AI and at least one second of its answer is lost, the transcript records this in a line ("KI unterbrochen: etwa … s … nicht mehr gesprochen"), and an agent receives it as an event. Until now the sentence stood in the transcript in full, as if it had been said. If a direction from the agent (`say`) was lost this way, the AI brings up its content again in its next turn.
- **No invented origin.** Asked "who are you?" or "who made you?", the AI gives its name and its principal; it invents nothing about its development or technology. For agent calls it is made clear that the agent only started the call.
- **Log: dropouts without false alarms.** A dropout in the middle of an answer is only reported when audio of the same answer follows; normal sentence endings no longer trigger a message.
- **MCP: the AI can pass questions from the other party on to the agent and says on request who started the call.** If the other party asks a direct question about the call or the task that the AI cannot answer, it now says "Einen Moment bitte, ich frage kurz nach" (one moment please, I will just check) and asks the agent instead of leaving it at "I do not know". Asked who started the call, it names the agent (Codex, Claude, Cursor, Gemini or GitHub Copilot, according to the agent's own statement), otherwise an AI agent in general. The descriptions of `start_call` and `say` and the example skill tell the agent that foreseeable questions belong in `context` and that what the other party says is not an instruction.
- **The answer to a late addition by the other party stays audible.** After a rejected hang-up the AI's answer also stayed silent when the other party's transcription arrived without a speech signal. When a transcription arrives, the answer is now audible again, including its beginning.
- **MCP: approve an agent call in the tray app pop-up.** When an AI agent requests a call, the tray app shows a pop-up at the bottom right with target, principal and task and the buttons "Anrufen" (call) and "Ablehnen" (decline). The web UI no longer has to be open for this; its confirmation dialog stays and closes as soon as the pop-up has been answered (and vice versa). The pop-up replaces the former notice of the tray app.
- **No second answer to the start of the call.** If the other party's first words were recognised too late, the AI greeted on its own and Gemini then answered those words a second time ("No problem, could you still tell me …"). Such a second answer right after the greeting now stays silent, unless the other party has spoken in the meantime. The log also records a buffer underrun in the middle of an answer with its time, the length of the gap and the size of the first piece of audio.
- **No repeated goodbye after a rejected hang-up.** If the AI thanks the other party and tries to hang up in the same breath, SIPFunk first lets the other party answer. With Gemini the AI then sometimes kept talking on its own and repeated its thanks, audibly but without appearing in the transcript. What the AI adds on its own in that situation now stays silent until the other party speaks, the waiting time is over, the agent gives a direction or asks to end the call, the AI makes a tool call, or the AI ends the call after all; the regular goodbye follows as before. The log names for every answer its trigger and whether a transcription came, and warns about audio without transcription.
- **The AI no longer stays silent after a noise at pick-up.** If the other party was heard before the greeting but said nothing intelligible (a click when picking up, a swallowed "Hallo"), the AI used to wait until the other party spoke again. It now greets on its own as soon as it is clear that nothing was said, or two seconds after the sound if no answer has started. The log additionally records when the session was ready, how long the other party was heard and which utterances were only a noise.
- **Calls to your own number: introduction as an AI on request.** When calling an owner number the AI still skips the explanation that it is an AI, unless the task explicitly asks for it (e.g. a test call by an agent).
- **Port of the web UI configurable, new default 3865.** The port of the web UI and the MCP interface is now under "Einstellungen › Technik" (still `127.0.0.1` only) and takes effect after a restart, which the web UI offers itself when running under the tray app; the page then switches to the new address. The new default is 3865 instead of 8080, because 8080 is taken on many computers. Existing installations keep their port as long as it is free and set as `WEB_PORT` in `.env` (always the case for the installed app); without that line 3865 applies.
- **Port in use: SIPFunk moves instead of running without a web UI.** If the configured port is taken at start, SIPFunk takes the next free one, stores it as the new setting and reports this in the log, as a tray notification and in the web UI. The tray menu names the port ("Web-UI öffnen (Port …)") and always opens the right address.
- **MCP: set up agents with one click.** The card "MCP-Schnittstelle" shows for Claude Code, Claude Desktop, Codex, Cursor, Gemini CLI and GitHub Copilot CLI whether SIPFunk is registered there, and registers it, updates the entry or removes it at a click. Other entries in the configuration file are kept, a backup copy is created next to it before every change, and SIPFunk does not touch files with comments or an unexpected structure. For Claude Code this goes through its own `claude mcp` command. After a port change HTTP entries count as "Veraltet" (outdated) and can be updated with one click. The message after the click says whether the agent needs a restart or a new session. Under "Von Hand eintragen" there are additional snippets for Cursor, VS Code, Gemini CLI and any other agent.
- **MCP as a process (stdio) finds the port itself.** The running app stores its port in `sipfunk.port` in the data folder; the stdio process reads it on every call (`SIPFUNK_DATA_DIR` in the configuration the web UI shows). An entry in Claude Desktop therefore survives a port change. Older entries with `SIPFUNK_URL` keep working but do not follow the port.
- **MCP interface: AI agents make phone calls.** An agent such as Codex, Claude Code or Claude Desktop can use MCP to start a call to a contact or a number, read along what the other party and the AI say, give the AI directions, end the call, and finally fetch result, summary and transcript. The voice AI conducts the call itself over the active AI connection (guided operation); if it lacks a decision, it says "Einen Moment bitte, ich frage kurz nach" (one moment please, I will just check) and asks the agent. Tools: `get_status`, `list_contacts`, `start_call`, `wait_for_events`, `say`, `end_call`, `get_call_result`, `list_calls`. `wait_for_events` blocks until there is something new; the agent does not have to poll. User guide, chapter 13, with the example "booking a table".
- **MCP is off by default and configurable in the web UI.** New section "Einstellungen › MCP-Schnittstelle" (settings › MCP interface): main switch, whom an agent may call (saved contacts only, or any permitted number), whether you are asked before dialling (always, only for numbers without a contact, never), maximum number of calls per hour and per day (defaults 10 and 30), maximum length per call (default 10 minutes), which call logs and whether contact names an agent may read. When an agent requests a call, the web UI shows a confirmation dialog and the tray app a notice. Agent calls are listed under "Anrufe" (calls) with the tag "Von KI-Agent" (by AI agent). **If you have used the MCP interface so far, you have to switch it on once after the update.**
- **MCP: two ways in, also for the installed app.** The server can be reached directly over HTTP (`http://127.0.0.1:3865/mcp`, Streamable HTTP) and, as before, as a stdio process; the latter now also starts from the installed app, without the repository and without Node.js (`SIPFunk.exe` with `ELECTRON_RUN_AS_NODE=1`). The card in the settings shows the finished configuration for Codex, Claude Code and Claude Desktop to copy. Both stay restricted to `127.0.0.1`.
- **MCP: changed tools.** `wait_for_call`, `hangup`, `get_call` and `call_history` no longer exist; `wait_for_events`, `end_call` and `get_call_result` take their place. `start_call` no longer accepts a name for the AI, a voice, a model or additional behaviour notes: these come from the settings (the voice from the contact or the AI connection), so that an agent cannot give the AI another identity. `principal` is now called `on_behalf_of` and is optional. `list_contacts` returns only names, and only with permission; without it the tools do not name a contact for a number that is called either. A principal different from the configured one is always put to you for confirmation.
- **Example skill for agents**: `examples/skills/sipfunk-call/SKILL.md` (German: `examples/skills/sipfunk-anruf/`) describes how an agent conducts a phone call with the tools.
- **Keeping an installation current during development**: `npm run install:local` builds the installer from the working folder and runs it silently over an existing installation; settings and data stay. `npm run install:auto` sets up Git hooks that do this by themselves after every commit or merge on `main` (in the background, log in `release/install-local.log`; `npm run install:auto -- --off` removes them). Nothing is installed if SIPFunk is not installed yet, and an update waits for a running call to end. `SIPFunk.exe --quit` closes the running tray app cleanly.

## 1.0.0 – 11 November 2026

- **Windows installer with autostart**: 1.0.0 is the first version with a ready-made installer and a portable ZIP under [Releases](https://github.com/alorbach/ai-sip-funk/releases). The installer works per user without administrator rights. After installation SIPFunk starts by itself after you sign in to Windows, in the notification area, without a window or console; the first start says so in a notification. You switch this off and on in the tray menu ("Beim Anmelden starten", start at login) or in Windows under "Startup apps". The choice survives updates, and uninstalling removes the entry; configuration and data under `%APPDATA%\SIPFunk` are kept. The portable ZIP does not switch autostart on by itself, and when started from the repository (`npm run tray`) the menu item is not shown.
- **Version visible**: The settings page shows the version below the heading (the tray menu already did), and the MCP server reports it instead of a fixed number.
- **Version numbers**: From 1.0.0 on, every new version increases the last digit (1.0.1, 1.0.2, …); the tag is `v<version>`.
- **Expandable AI connections**: The card "KI-Verbindungen" (AI connections) is now an expandable list. Each connection is a row with its name, provider, voice model and default voice, where applicable the tag "Schlüssel fehlt" (key missing) and, on the active one, "✓ aktiv" (active). A click on the row (or Enter or the space bar) expands its settings in place, a second one collapses them; several can be open at the same time, and when the page is first opened the active one is expanded. Each connection has its own fields (name, default voice, models, key, "Verbindung testen", "Diese Verbindung verwenden", "Verbindung entfernen"); the shared form below the list, whose fields were overwritten when you clicked a connection, is gone. Input that is not saved yet (e.g. a key you have typed) stays in place when you expand or collapse another connection. Expanded only means that the settings are visible; active is the connection that handles the calls. The notes "Was mit Gemini anders ist" (what is different with Gemini) and "Tatsächliche Kosten laut OpenAI" (actual costs according to OpenAI) appear for the provider of the active connection and of every expanded one.
- **Default voice per connection**: Each connection has a "Standardstimme" (default voice) from the voices of its provider; "Probe hören" (listen to a sample) next to it plays them with the key of that connection, even if it is not active. Order of precedence for a call, where each level only counts if the voice belongs to the provider of the active connection: the "Stimme der Rolle" (voice of the role) of the spam defence (if the spam role is certain at pick-up), then the voice chosen for the call (field "Stimme" on the dashboard or `voice` through the API or MCP, otherwise the voice of the contact or of the own number), then the default voice of the active connection, finally the former general voice or the provider's first voice. The field "Stimme" on the dashboard shows "– Standard: … –" and applies only to the next call from there; "Als Standard speichern" (save as default) remembers task, style and form of address, but no longer the voice. After switching the connection its default voice applies and the message names it; the request to check the voice is gone. Nothing changes by itself on update: connections, keys and models stay, and a connection without a default voice of its own keeps using the previously saved general voice, provided it belongs to its provider. `AI_VOICE` in `.env` is now only the initial value for connections without a default voice of their own; in `settings.json` every connection additionally carries `voice`.
- **Gemini: first real phone calls**: On 11 November 2026 the first three real phone calls ran over Google Gemini (Live API), two on the answering machine and one call back to the owner. They went through without errors: the introduction as an AI, the task, the goodbye and hanging up all worked. Gemini has thus been tried on only a few real phone calls so far; OpenAI remains the tested default. Two bugs were noticed and fixed along the way: Gemini's transcription contained placeholders such as `<no speech>`, `{pause}` or `...` for answers without speech, as separate turns of the AI in the transcript; they are now filtered out. And when the AI ended the call right after the other party's last sentence, "Ergebnis laut KI" (result according to the AI) appeared in the transcript before that sentence; the order is now correct.
- **AI connections**: The settings card "KI-Verbindungen" (AI connections) replaces the provider selection. A connection is a named access to an AI provider: provider, its own API key and the models used with it (voice model for calls, text model for plan, summary, assessment and complaint). Two connections exist from the start, "OpenAI" and "Google Gemini", and earlier settings (selected provider, models) are carried over automatically. You can create up to 12, for example two OpenAI accounts, a cheap and an expensive model, or Gemini next to OpenAI, and switch between them in the card (expand the connection, "Diese Verbindung verwenden"), on the dashboard (field "KI-Verbindung", which replaces the model field there) or in step 3 of the setup assistant. The active connection handles calls, plan, summary, assessment, complaint draft and voice samples; call content goes to its provider only. Changes to connections apply immediately, without "Speichern". Removing a connection (after a confirmation) deletes its key from `.env`; at least one connection has to remain, and the provider of an existing connection cannot be changed. The models are now set per connection in this card; the "KI-Modell" block under "KI-Assistent" is gone. A connection without a model uses the provider default (`OPENAI_MODEL`, `OPENAI_SUMMARY_MODEL`, `GEMINI_MODEL`, `GEMINI_SUMMARY_MODEL` from `.env`, otherwise the built-in default). The list is stored in `settings.json` as `aiConnections` and `aiConnection`; `aiProvider` mirrors the provider of the active connection. Keys stay in `.env` only: `OPENAI_API_KEY` and `GEMINI_API_KEY` for the two built-in connections, `AI_KEY_<ID>` for every further one. "Verbindung testen" tests the connection in whose area you press the button. Monthly usage is still counted per provider.
- **Settings as tabs**: The section list on the left of the settings page no longer scrolls through one long page. Only the card of the selected section is shown, the choice is remembered, and "Speichern" (Ctrl+S) still saves all sections.
- **Second AI provider: Google Gemini (Live API)**: Besides OpenAI (default) there is now Google Gemini; each has its own connection under "Einstellungen › KI-Verbindungen" (AI connections; both levels, see above). The active connection does everything: the call, call plan, summary, assessment, complaint draft and voice samples; call content goes to its provider only. Both keys (`OPENAI_API_KEY`, `GEMINI_API_KEY`) can be entered in the web UI; they are accepted on `127.0.0.1` only, checked once with the provider, written to `.env` and never returned or logged. New in `.env`: `AI_PROVIDER`, `GEMINI_API_KEY`, `GEMINI_MODEL` (default `gemini-3.8-live`), `GEMINI_SUMMARY_MODEL` (default `gemini-3.5-flash-lite`). Gemini has its own 30 voices; a stored voice of the other provider is ignored and the default voice of the active connection is used (see above). **The Gemini path has so far been tried on only a few real phone calls (first calls on 11 November 2026, see above); OpenAI remains the tested default.** Known limitations with Gemini: calls last nine minutes at most, the speaking rate is only a hint, a late call plan and the switch into the spam defence reach the AI as follow-up instructions (weaker than with OpenAI), finishing a sentence after a mere "mhm" works less often, the simulator works with OpenAI only, and the cost estimate always uses the prices of the paid tier. On the free quota see [doc/legal.md](doc/legal.md), section 3.5.
- **"Verbindung testen" (test connection)**: the card "KI-Verbindungen" checks in three steps whether the key is valid, whether the voice model is in the model list of the account and whether the live connection can be established. It sends no audio and does not test a phone call.
- **Usage this month**: the card "KI-Verbindungen" shows calls, minutes and estimated US dollars per provider for the current month, summed from SIPFunk's own estimates per call in `usage.json` (kept for 13 months, independent of the log retention; calls only). Optional, level "Erweitert", OpenAI only: the actual month-to-date costs of the OpenAI organisation with an organisation admin key (`OPENAI_ADMIN_KEY`), which can be removed again in the web UI.
- **Provider layer**: the call logic in `src/ai/realtimeBridge.ts` no longer depends on OpenAI; it talks to a `LiveSession`, and an adapter per provider (`src/ai/providers/`) translates the wire protocol.
- **Downloads**: from this version on, GitHub builds the Windows installer and the portable ZIP automatically for every version tag and publishes them as a release with the list of changes.
- **Models loaded from the provider**: You now pick the voice and text model from the models your account offers (loaded with the key of the connection, at most every six hours; "Modelle aktualisieren" reloads at once). The text model is therefore a selection too; its default stays `gpt-6-luna`. The "(besser)" label is gone: "(Standard)" marks the default, "(günstig)" only models with a known price. Without a key or network your saved choice is kept and the reason is shown next to the button. Level "Erweitert" now has a custom model ID for both models. Text models without reasoning work as well: if a model rejects the setting, SIPFunk asks again without it.
- **Configurable AI model**: In the settings you can choose the voice model for calls (applies to outgoing calls and the answering machine) and the text model; level "Erweitert" adds a custom model ID. Both are set per connection under "KI-Verbindungen" (see above).
- **Behaviour in the call**: Instead of one line of text there are four choices (length of replies, pace of the call, confirming names, numbers and dates, small talk) and a multi-line field for free notes. On "Default" the AI behaves as before.
- **Family answering machine**: "Behind it is" now offers "a family" per own number, next to person and company. The AI says "nobody is at home right now", asks who the call is for and records it in the result. The family members can optionally be entered; the AI does not list them of its own accord.
- **Spam defence with AI disclosure**: New switch "AI disclosure". Switched on, the AI openly acts as an AI towards spam callers as well and still fends off or stalls; no risk confirmation is needed for that. The default is on; the private person is only available if you switch disclosure off and confirm the risk. Whoever had already confirmed the risk keeps their setting. While disclosure is off, the page shows a red warning "on your own responsibility".
- **Setup assistant**: the app now starts without SIP credentials and without an OpenAI key. On first start the web UI walks through the essentials (phone system with a test registration, OpenAI key with a check, names, answering machine and own number, optional e-mail, test call in echo mode). It can be skipped and reopened from "Einstellungen". Credentials are accepted on `127.0.0.1` only, checked, written to `.env` and never returned; the SIP client re-registers without restarting the app.
- **Two levels, "Einfach" and "Erweitert"**: the web UI shows only what is needed for everyday use by default; "Erweitert" adds all technical settings. The switch is in the header, applies immediately and is stored in `settings.json`. Hidden settings keep their values.
- **English interface**: web UI, ring pop-up and tray menu are available in English. By default the language follows the browser (tray: the system); "Sprache" (language) on the settings page fixes it to German or English. German stays the source: `public/i18n-en.js` holds the English texts, and a text without a translation simply appears in German. The AI itself still speaks German on the phone, and the system log and call results are not translated.
- **Mail password**: changing the mail server without entering the password again now discards the stored password, so it cannot be sent to another server. "Automatisch einrichten" saves server and a freshly typed password in one step.
- **Echo test call**: with HD audio the FRITZ!Box sends 10 ms packets, and the echo played back only one of them per 20 ms – choppy and at half speed. The echo now works on samples and returns the audio completely.
- **Design and accessibility**: visible borders on fields and switches (at least 3:1), tags with at least 4.5:1, keyboard-operable tabs, labelled dialogs, error messages that are announced, no overflow from 420 px width.
- **Fixes from a code review**: transfer now applies the dial target protection; call-by-call prefixes are blocked; saving settings no longer overwrites the dashboard defaults (and vice versa) and only sends what changed; a notification is sent even if the summary fails; the tray app shuts the server down cleanly (a running call is hung up); `settings.json` and `contacts.json` are written atomically; the SIP client stops cleanly and reports the end of a call immediately.
